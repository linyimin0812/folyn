# 2026-09-18

## 扩展弹窗全局置顶（桌宠触发 sandbox 弹窗只能在 folyn 上层打开）

- 根因：`open_extension_tool_window` 的 macOS 分支此前用 `canJoinAllSpaces | stationary | fullScreenAuxiliary`（273）收集行为。本项目自己的记录（lib.rs `reapply_pet_topmost` 注释）证实：`canJoinAllSpaces` 对普通 NSWindow 无效（全屏应用上 `isOnActiveSpace` 保持 false），窗口被绑死在 Folyn 所在 Space → 弹窗只出现在 folyn 应用上层。
- 修复（对齐 `.trellis/spec/desktop/frontend/tauri-window-patterns.md` 未提交的设计）：
  - `pet_panel_macos.rs` 新增 `convert_window_to_floating_panel(&WebviewWindow) -> bool`：裸 `msg_send!`（走 `tauri_nspanel::objc2` 重导出）设置 ScreenSaver level（CGWindowLevelForKey(13)）+ `moveToActiveSpace | fullScreenAuxiliary | fullScreenAllowsTiling`（770，pet 验证过的配方）+ `orderFrontRegardless`（不激活应用、不绑 IMK observer）。包 `objc2::exception::catch`。不用 `to_panel()`（动态创建窗口 contentView 未挂载时会 panic）。
  - `webview_commands.rs` `open_extension_tool_window`：命令开头用 `tool_key_from_label` 扫描 `webview_windows()` 实现单例（已存在则重新浮起并返回原 label；原生全屏窗口跳过层级重申以免踢出全屏 Space；macOS 重申层级防 AppKit/tauri 降级回 Floating）；新建路径 macOS 分支改为调用上述辅助函数。
  - 前端 `toolWindowStore.ts` / `petHostRouter.ts` 已在此前会话改好（label 去重、不 focusMain），本次未动。
- 注意：会话中途 `webview_commands.rs` 被外部（用户或并行会话）修改过一次（15:07，内联代码已从 273 改成 770），我在其基础上收敛为辅助函数调用，保留了根因注释。
- 验证方式：按 AGENTS.md 不跑全量编译；msg_send/objc2/catch 模式对照 voice.rs、pet_panel_macos.rs 已编译代码，`is_fullscreen/is_minimized/unminimize` 对照 Tauri 2.11.2 源码确认存在。待用户自行构建验证实际浮层效果。
