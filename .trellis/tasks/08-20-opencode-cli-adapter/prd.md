# opencode cli adapter

## Goal

Add an `opencode` CLI adapter to `packages/cli-adapter`, so Quill can drive
the [opencode](https://opencode.ai) CLI as a coding-agent backend with the
same streaming/resume UX as claude/codex/pi/qoder. Wire it into the desktop
shell sidecar allowlist, add an icon, and surface it in the three adapter
UIs so users can pick it.

## Requirements

- `packages/cli-adapter/src/opencodeAdapter.ts` — new adapter class modeled
  on `qoderAdapter.ts` (one-shot spawn per send) with a **fresh**
  `translateOpencodeEvent` (opencode's wire shape is NOT codex/qoder-
  compatible — see Research References).
- Pure seams (unit-testable without spawning):
  - `translateOpencodeEvent(event)` — map opencode NDJSON events to
    `CliStreamEvent[]`.
  - `buildOpencodeArgs(prompt, options)` — arg vector for first send +
    resume.
  - `buildOpencodeShellCommand(cliPath, workingDir, args)` — compose
    `/bin/sh -lc` command.
  - `resolveOpencodeCliPath(cliPath, adapterId, cliPathDefault)` — same
    id-vs-binary-name fallback as qoder.
- `packages/cli-adapter/src/registry.ts` — register `opencode` adapter id
  with `settingsFilePath = '~/.config/opencode/opencode.jsonc'`,
  `settingsFileTemplate = '{\n  "$schema": "https://opencode.ai/config.json"\n}\n'`.
- `packages/cli-adapter/src/opencodeAdapter.test.ts` — unit tests for all
  pure seams, covering: `step_start`→session_id capture, `text`→text,
  `tool_use` fused event → `tool_start` (+ `tool_end` when status is
  completed/error), `step_finish` ignored, unknown type → `[]`, arg
  vector (first send + resume), shell command (with + without workingDir),
  cliPath fallback.
- `apps/desktop/src-tauri/capabilities/default.json` + `pet-panel.json` —
  add `opencode-cli` sidecar entry in both `shell:allow-spawn` and
  `shell:allow-execute` allow lists (mirrors qoder-cli entries).
- `apps/desktop/src-tauri/gen/schemas/capabilities.json` — regenerated by
  Tauri (auto; touch if needed).
- `apps/desktop/src/assets/agents/opencode.svg` — new icon.
- `apps/desktop/src/components/ai/AdapterSelector.tsx`,
  `apps/desktop/src/components/ai/AgentCliTag.tsx`,
  `apps/desktop/src/components/settings/FeatureAdapterDropdown.tsx` —
  add `import opencodeIcon` + `opencode: opencodeIcon` entry to each
  `ADAPTER_ICON` map.

## Technical Approach

Model on `qoderAdapter.ts`'s one-shot spawn lifecycle; write a fresh
translator. Per `research/opencode-cli-shape.md`:

- **Spawn**: `opencode run --format json --auto [--dir <workingDir>] [-s
  <sessionId>] <prompt>`. Sidecar name `opencode-cli`; binary `opencode`.
- **Wire shape** (per line, NDJSON):
  - Envelope: `{type, timestamp, sessionID, part}`.
  - `step_start` → capture `sessionID` (first event); no-op otherwise.
  - `text` → `{type:'text', content: part.text}`.
  - `tool_use` → emit `tool_start` always; emit `tool_end` (with
    `part.state.output`) when `part.state.status === "completed"`;
    emit `tool_end` + `error` content when `status === "error"`. Fused
    event — `tool_start` may not be followed by a separate `running`
    event (caveat in research §4.3).
  - `step_finish` → ignore (reason "stop" is not the done signal).
  - Unknown type → `[]`.
- **Done**: `command.on('close')` is the authoritative `done` signal
  (opencode emits no terminal `result` event). Non-zero exit or stderr
  line → `error` + `done`.
- **Resume**: `-s <sessionId>`; persist `sessionId` from the first event's
  top-level `sessionID`.
- **stdin**: no `< /dev/null` needed (opencode doesn't block on stdin,
  research §6); include anyway for symmetry with qoder/codex — harmless.
- **workingDir**: use `--dir <workingDir>` (opencode native flag) instead
  of shell `cd` wrapper when workingDir is set — cleaner than the qoder
  pattern, and opencode already has the flag.

## Decision (ADR-lite)

**Context**: opencode's wire shape is not codex/qoder-compatible (no
`system`/`assistant`/`result` envelope, no terminal `result` event, tool
call start+result fused into one `tool_use` event with
`part.state.status`).

**Decision**: model the spawn lifecycle on qoderAdapter (one-shot spawn
per send, `command.on('close')` as `done` fallback), but write a fresh
`translateOpencodeEvent` that handles opencode's envelope + fused
`tool_use` event. Emit both `tool_start` and `tool_end` from the fused
event (more useful than qoder's `tool_start`-only shape, since opencode
already carries `output`).

**Consequences**:
- Pro: full tool lifecycle visible to the UI (qoder only emits
  `tool_start`).
- Con: long-running tool event shape (whether a separate
  `status:"running"` event precedes the completed one) was not observed
  live — translator handles both cases (one fused OR running-then-
  completed pair). Update on first real failure.
- Con: error event shape not observed; rely on stderr + non-zero exit.

## Out of Scope

- China variant (`opencode-cn`) — opencode has no separate China binary;
  China routing is a provider config concern (research §1, §9).
- `opencode plugin` / `agent` / `mcp` subcommand wiring — out of scope,
  matches qoder precedent (plugins/agents exist but aren't wired).
- i18n `cli.adapters.opencode` entry in `settings.json` — codex/qoder
  don't have one either; the registry `description` is used directly.
- `--thinking` reasoning blocks — skip for MVP (qoder doesn't surface).
- Auto-login via `opencode providers login` — out of scope; user runs
  out-of-band (matches qoder precedent).
- Session list/import/export subcommands — out of scope.
