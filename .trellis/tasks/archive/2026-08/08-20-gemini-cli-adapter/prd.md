# gemini cli adapter

## Goal

Add a `gemini` CLI adapter to `packages/cli-adapter`, so Folyn can drive the
[Gemini CLI](https://github.com/google-gemini/gemini-cli) as a coding-agent
backend with the same streaming/resume UX as claude/codex/pi/qoder/opencode.
Wire it into the desktop shell sidecar allowlist, add an icon, and surface it
in the three adapter UIs so users can pick it.

## What I already know

- Binary `gemini` (npm `@google/gemini-cli`, v0.56.0) installed locally at
  `/Users/yiminlin/.nvm/versions/node/v25.9.0/bin/gemini`.
- Wire shape mapped from installed bundle source — six NDJSON event types:
  `init`, `message`, `tool_use`, `tool_result`, `error`, `result`. See
  `research/gemini-cli-shape.md` for full source citations.
- `result` event is the explicit terminal done signal (closer to codex than
  opencode). Assistant text is delta-streamed (`message` with `delta:true`,
  multiple per turn). Tool start/end are two separate events paired by
  `tool_id`.
- Existing adapter pattern: model on `qoderAdapter.ts` (one-shot spawn per
  send, shell `cd` + `< /dev/null`), register in `registry.ts`, add sidecar
  to `default.json` + `pet-panel.json`, add icon + wire three `ADAPTER_ICON`
  maps. No i18n entry (codex/qoder/opencode precedent).

## Technical Approach

Model on `qoderAdapter.ts`'s one-shot spawn lifecycle; write a fresh
translator. Per `research/gemini-cli-shape.md`:

- **Spawn**: `gemini -p <prompt> -o stream-json -y --skip-trust` (resume:
  append `-r <sessionId>`). Sidecar name `gemini-cli`; binary `gemini`.
  `--skip-trust` is required on every spawn (Folyn workingDirs are not
  pre-trusted).
- **Wire shape** (per line, NDJSON — six `type` values total):
  - `init` → `{type:'session_id', sessionId: event.session_id}` (capture
    for resume; emitted once at run start).
  - `message` with `role:"assistant"` → `{type:'text', content:
    event.content}` (each event is a token delta — emit each, UI appends).
  - `message` with `role:"user"` → `[]` (prompt echo, no-op).
  - `tool_use` → `{type:'tool_start', toolName: event.tool_name, toolId:
    event.tool_id, toolInput: event.parameters ?? {}}`.
  - `tool_result` → `{type:'tool_end', toolId: event.tool_id, toolOutput:
    event.output ?? ''}`; when `status === "error"`, also emit
    `{type:'error', content: event.error.message}`.
  - `error` with `severity === "error"` → `{type:'error', content:
    event.message}`; `severity === "warning"` → `[]` (run continues —
    warning is not terminal).
  - `result` with `status:"success"` → `[{type:'done'}]` (terminal).
  - `result` with `status:"error"` → `[{type:'error', content:
    event.error.message}, {type:'done'}]` (terminal).
  - Unknown type → `[]`.
- **Done**: `result` event is the authoritative terminal signal (codex-
  like, not opencode-like). `command.on('close')` remains as a fallback —
  whichever fires first resolves the send promise; the second is a no-op
  duplicate (guard with `this.running` flag like qoder does).
- **Resume**: `-r <sessionId>`; persist `sessionId` from the first `init`
  event's `session_id` field.
- **stdin**: always `< /dev/null` — Gemini's 500ms stdin-wait timer makes
  every send pay 500ms latency otherwise (research §6). Load-bearing, not
  just defensive.
- **workingDir**: shell `cd <workingDir> && exec gemini …` — Gemini has no
  `--dir` flag (unlike opencode), so we mirror the qoder/codex shell
  wrapper pattern verbatim.
- **Model pin**: optional `-m <model>` if the user pins a model (mirror
  qoder precedent).

## Decision (ADR-lite)

**Context**: Gemini CLI's wire shape differs from all three existing
adapter shapes — six explicit event types with an authoritative terminal
`result` event (codex-like), delta-streamed assistant text (multiple
`message` events per turn), and separate `tool_use` + `tool_result`
events paired by `tool_id` (unlike opencode's fused single event).

**Decision**: model the spawn lifecycle on `qoderAdapter.ts` (one-shot
spawn per send, shell `cd` + `< /dev/null`), but write a fresh
`translateGeminiEvent` that handles the six-type envelope. Use `result` as
the authoritative `done` (codex-like) with `command.on('close')` as a
fallback. Emit `tool_start` + `tool_end` from two separate events (cleaner
mapping than opencode's fused event).

**Consequences**:
- Pro: clean tool-lifecycle mapping (two events → two Folyn events, paired
  by `tool_id`).
- Pro: explicit terminal `result` event gives a more reliable `done` than
  opencode's process-exit heuristic.
- Con: **no live `stream-json` run captured** — the Gemini API endpoint is
  unreachable from this machine. All payload shapes are reconstructed from
  installed-bundle source grep (`bundle/gemini-KK7AERSF.js` emit points +
  `chunk-MYCBWRZE.js` enum). The two shapes already confirmed by a partial
  real run match the source exactly; the rest are verified-by-source only.
  Live verification is deferred — re-run with a reachable API endpoint on
  first authenticated test and update the translator if any field is off.
- Con: assistant text delta-streaming (multiple `message` events per turn)
  was not observed live — the translator emits one `text` event per delta;
  verify the Folyn UI appends rather than overwrites on first real run.

## Out of Scope

- China variant (`gemini-cn`) — Gemini has no separate China binary;
  routing is a model/provider config concern (research §1).
- `gemini mcp` / `gemini extensions` / `gemini skills` / `gemini hooks` /
  `gemini gemma` subcommand wiring — out of scope, matches qoder/opencode
  precedent (subcommands exist but aren't wired).
- i18n `cli.adapters.gemini` entry in `settings.json` — codex/qoder/opencode
  don't have one either; the registry `description` is used directly.
- Auto-login — out of scope; Gemini has no `auth` subcommand (unlike
  opencode's `opencode providers login`). Auth is configured entirely via
  `~/.gemini/settings.json`'s `security.auth.selectedType` + env vars
  (`GEMINI_API_KEY`); the user sets these out-of-band.
- `--thinking` / reasoning blocks — skip for MVP (qoder doesn't surface).
- `stats` capture from `result` event — skip for MVP (UI doesn't render
  usage stats yet; add when the UI asks for them).
- `--approval-mode` flag — use `-y/--yolo` short form instead (matches
  opencode's `--auto` precedent).
- OAuth / Vertex AI auth paths — out of scope (only API-key auth inspected
  locally; other flows are documented elsewhere).
- Session list/import/export subcommands — out of scope.
