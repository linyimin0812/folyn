# 知识库生成物存应用数据目录，按 Vault 隔离

2026-10-28，选择把知识库生成物（manifest、索引、引用时快照、主题知识页、refs、审阅、删除意图、主题目录）存放在 `~/.folyn/vaults/<vaultId>/__kb__/`，复用版本历史的按 Vault 应用数据根；目录内部布局不变。源资料（用户自己的文件）仍留在 Vault 内，读取链路不变。

未选择继续把生成物放在 `<vault>/__kb__/`。该目录污染 Vault 的文件阅读体验：在文件树中可见、会被同步与备份工具打包，与 Vault 作为用户资料集的边界冲突。这一决定取代 ADR-0009 中「随 Vault 携带」的存储位置结论；以文件为真源的原则不变——生成物仍是普通文件，只是换了根。

## 路由按前缀，逻辑路径不变

路径派生（`__kb__/...`）与执行层解耦：`__kb__` 前缀的路径在适配层解析为 `~/.folyn/vaults/<vaultId>/` 下的绝对路径，直写文件系统；其余路径（源资料）仍按 Vault 相对路径走既有 manager。manifest 中记录的主题页路径保持原语义，不随存储根变化。

未选择把路径派生改为绝对路径或在 manifest 中存绝对路径。绝对路径不可移植，且会让纯逻辑（可测试的同步路径函数）依赖异步 base 解析。前缀路由使既有消费方（构建、阅读、问答、审阅、核验）零改动。

## 不做存量迁移

已有 Vault 的旧 `<vault>/__kb__/` 数据留在原地，由用户自行处理（收录范围本就排除该目录，不会循环收录）；新位置从空态起步，与全新 Vault 一致。需要旧数据时后续可提供导出/迁移工具。

未选择自动迁移。静默搬运用户可见目录容易与同步工具的副本产生分歧；一次性迁移代码只为淘汰中的数据服务。

## 后果

知识库生成物不再随 Vault 同步或备份携带（`~/.folyn` 本就是应用数据目录）；KB 数据的多机同步与备份由后续的导出能力解决。Vault 内不再产生 `__kb__` 写入；Vault watcher 看不到 KB 文件的变更，对 KB 路径的写入抑制成为无害空操作。引用时快照与主题页在编辑器中打开时按绝对路径处理（外部文件先例同 drops）。
